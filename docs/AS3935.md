# AS3935 Lightning Detector

Optional AS3935 lightning support was introduced in `0.3.0-dev` as an auxiliary application-layer sensor.

The AS3935 subsystem is **independent of the Davis RF receiver**. Enabling or disabling it does not change the SX1276 Davis FHSS configuration or packet decoder.

## Electrical interface

The AS3935 uses the same I2C bus as the BME280 plus a dedicated IRQ GPIO.

Common AS3935 addresses are `0x01`, `0x02` and `0x03`; the default configuration uses `0x03`.

The gateway runs the shared I2C bus at 100 kHz for compatibility and diagnostics.

## Board defaults

### LILYGO / TTGO T3 V1.6.1

```text
I2C SDA     GPIO21
I2C SCL     GPIO22
AS3935 IRQ  GPIO34
Address     0x03
Enabled     yes
```

GPIO34 is input-only, which is suitable for the AS3935 interrupt output.

### LILYGO T3-S3

```text
I2C SDA     GPIO18
I2C SCL     GPIO17
AS3935      disabled by default
IRQ         not assigned by default
```

The T3-S3 profile deliberately requires an installer-selected IRQ pin because board revisions/peripherals may use different GPIOs. The firmware rejects an AS3935 IRQ that conflicts with configured radio, I2C or LED pins.

## Runtime configuration

Configuration is stored in NVS namespace `as3935cfg` and includes:

- enabled/disabled;
- indoor/outdoor AFE mode;
- I2C address;
- IRQ GPIO;
- noise floor threshold `0..7`;
- watchdog threshold `0..15`;
- spike rejection `0..15`;
- minimum strikes: `1`, `5`, `9` or `16`;
- disturber masking;
- tuning capacitor `0..15`;
- optional automatic resonance tuning.

## Startup and calibration

When enabled the manager:

1. validates the pin/address configuration;
2. checks the I2C connection;
3. validates or auto-tunes the antenna resonance;
4. calibrates the internal RCO;
5. applies detection thresholds and AFE mode;
6. attaches the IRQ interrupt.

A calibration state of `CHECK` does not modify Davis RF operation; it only indicates that the lightning subsystem needs hardware/tuning verification.

## Events

The manager tracks:

- total IRQs;
- noise events;
- disturber events;
- lightning events;
- last interrupt source;
- last detected storm distance;
- out-of-range distance state;
- last lightning energy;
- last event and lightning timestamps in `millis()` domain.

The AS3935 distance code `0x3F` is treated as out of range rather than as a numeric distance.

## Web APIs

GET:

```text
/api/as3935/state
/api/as3935/config
```

POST:

```text
/api/as3935/config
/api/as3935/reinit
/api/as3935/reset
```

The main dashboard displays detector status, calibration, resonance, noise/disturber/lightning counters and last strike distance.

## MQTT

When MQTT is connected the manager publishes:

```text
<base>/as3935/state
<base>/as3935/event
```

The state topic is retained. Event messages are non-retained.

## Diagnostics

Use `/api/i2c/scan` to verify the physical AS3935 address and BME280 presence. The scan is intentionally on-demand because it temporarily uses the shared I2C bus.

Recommended field checks:

- verify stable I2C presence;
- verify IRQ transitions and `irq_total`;
- check resonance/calibration status;
- validate noise floor in the final enclosure/location;
- compare known storm activity with lightning/distance output;
- confirm no RF packet-loss increase after installing sensor wiring.

The last item is important because physical wiring/noise can affect the complete device even though the AS3935 software module is separate from the Davis RF engine.
